# Dedicated host legacy-history exclusion candidate

This successor adds an immutable process opt-in, `-SpeedExactRemoteDedicatedHost`, for the new dedicated Demo path. In a game world it requires NM_DedicatedServer, canonical owned Normal execution, and rejects missing or already registered/history-bearing legacy network components before any mutation. It does not unregister, remove, adopt or replay live histories. The default route still creates the existing histories for standalone/SL.

Inside `USpeedWheeledComponent::OnCreatePhysicsState`, before the legacy registration block, the opt-in excludes `SNetworkPhysicsComponent` (`PC_SpeedNetPCName`, `FPhysicsSpeedTraits`) and `WheeledNetworkPhysicsComponent` (`PC_WheeledNetPCName`, `FPhysicsWheeledTraits`) plus their network settings registration. Both components become nonreplicated. `IsLegacyNetworkHistoryExcluded()` is a GT-only witness of their unregistered state and absent External input/state histories; no PhysicsThread history getters are called on GT. Normal Chaos vehicle storage construction remains unchanged.

`ConfigureExactRemoteInputHost` now also requires the same flag, canonical owned Normal profile and300Hz before its existing dedicated-only, pre-worker, pre-admission check. The future Demo driver will be nonreplicated from construction; client proxies will contain no wheeled movement component. This source-only successor is not qualified by the previous native61f565e results. Native compilation, dedicated exclusion assertions and the real two-client test must run on a fresh Demo tuple. No public publication or SL activation is claimed.

The shared read-only API is `Speed::Netcode::QueryExactRemoteHostPolicy(const UWorld*)` in `Netcode/remote-input/ExactRemoteDedicatedHost.h`: Legacy, IsolatedDedicated or Invalid. It centralizes flag, dedicated role, canonical owned Normal execution and300Hz conditions. A caller must reject Invalid rather than falling back. IAS owns its two component checks; SL Core may independently validate/exclude its third Skycar history under this same policy, without copying the profile criteria. The peer owns that Core hunk and no Core adoption is made here.

The successor also adds owner-only `CompleteOwnedWorkerAtBoundary()` (default false) and `ESimulationBoundaryResult::Complete`. Completion is serviced before exact-input admission, so a bounded probe can stop normally even when the next remote frame is absent. The worker still closes/retire its ledger on its owner. This avoids GT invalidation racing the subclass's post-commit common-packet witness, and does not fabricate a final input/frame. RemoteCanonicalTrajectories now prepares this boundary-completion path for native verification; it is not yet rerun on this successor.
